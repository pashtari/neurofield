    FUTON, bases and combiners¶

    The FUTON concept page derives the model; this page is the reference for neurofield.models.futon: FUTON and its encoding, FUTONEncoding, the bases and combiners, and the SharedRows and Taps features its bases return on grids and for local bases.

    futon ¶

    FUTON: coordinate bases, tensor-network combiners, and the FUTON model.

    FUTON evaluates decoder(combiner(basis(x))) in three stages:

    1. A basis maps coordinates (N, C) in [-1, 1] to one feature tensor (N, K_c) per axis, where K_c = num_components[c].
    2. A combiner projects the features of each axis and combines the projections into one (N, out_features) tensor.
    3. A decoder, nn.Linear or MLP, maps the fused features to the output.

    The first two stages make up FUTONEncoding, which FUTON decodes.

    Every basis takes num_components, an int shared by all axes or one count per axis; normalize, which L2-normalizes each feature vector (not each basis function); and grid_size, the sizes of the grid its inputs lie on, if they do. The local bases TriangleBasis and LanczosBasis default to sparse mode: off a grid, each axis returns Taps, only the few nonzero features of each point.

    On a grid, where every axis of a flat batch repeats its coordinates, a basis evaluates each distinct coordinate once, or reads the table of the grid that its grid_size declares, evaluated once when it is built, and returns each axis as SharedRows of that table: the combiners then project the table rather than every point, the same function at a fraction of the cost. Both kinds multiply like (N, K_c) matrices, so every combiner treats every axis alike; compiled, the gathers fuse with the product and the decoder.

    SharedRows ¶

    Bases: NamedTuple

    An axis's features on a grid: (N, K), row n being table[rows[n]].

    table holds the features of S coordinates of the axis, its distinct ones or those of its grid, and rows the row of each point, so a product with a factor projects S rows rather than N.

    Taps ¶

    Bases: NamedTuple

    An axis's local features off a grid: (N, size), row n holding the L values values[n] in columns start[n] to start[n] + L - 1.

    compiled records whether a compiled graph made the taps, whose product with a factor then gathers windows of its rows.     TuckerCombiner ¶

    TuckerCombiner(in_features: Sequence[int], rank: int | Sequence[int], out_features: int | None = None)

    Bases: _Combiner

    Tucker combiner.

    Projects axis c to rank[c] channels with its factor factors[c] of shape (K_c, rank[c]), as the CP combiner does, and contracts the projections with a core of shape (rank[0], ..., rank[C - 1], out_features) instead of multiplying them elementwise: with a linear decoder the weight tensor is in Tucker format, the core with one factor matrix per axis and the decoder as the last. CP is the special case of a superdiagonal core. This extends the paper's CP model. The core absorbs one projection at a time, largest rank first.

    self,
    in_features: Sequence[int],
    rank: int | Sequence[int],
    out_features: int | None = None,
) -> None:
    super().__init__(in_features)
    modes = len(self.in_features)
    self.rank = _broadcast(rank, modes, "rank")
    self.out_features = max(self.rank) if out_features is None else out_features
    self.factors = nn.ParameterList(
        nn.Parameter(torch.empty(width, r))
        for width, r in zip(self.in_features, self.rank)
    )
    self.core = nn.Parameter(torch.empty(*self.rank, self.out_features))
    # The core absorbs one projection at a time, largest rank first, so
    # the intermediates stay smallest and lead with the points (the
    # ellipsis); opt_einsum's own optimum starts with an outer product of
    # the projections, slower and larger. Each result goes to the end of
    # the operands, hence the path; given the path, the points' count of 1
    # is a placeholder.
    self.order = sorted(range(modes), key=self.rank.__getitem__, reverse=True)
    self.contract = oe.contract_expression(
        tuple(self.core.shape),
        [*range(modes + 1)],
        *(arg for c in self.order for arg in ((1, self.rank[c]), [..., c])),
        [..., modes],
        optimize=[(0, 1)] + [(0, n) for n in range(modes - 1, 0, -1)],
    )
    self.reset_parameters()

    FUTONEncoding ¶

    FUTONEncoding(in_features: int, basis: ModuleSpec, combiner: ModuleSpec)

    Bases: Module

    FUTON's encoding: the features of a basis, fused by a combiner.

    Computes combiner(basis(x)), which FUTON decodes. Each stage is given as for FUTON.

    Parameters:

    Name Type Description Default
    in_features int

    Number of coordinate axes C.

    		 required
    basis ModuleSpec

    Basis spec, built as basis(in_features, **kwargs). Custom bases must expose num_components, one count per axis.

    		 required
    combiner ModuleSpec

    Combiner spec, built as combiner(basis.num_components, **kwargs). Custom combiners must expose out_features, the encoding's width.

    		 required
    Shape
    • Input: \((N, C)\) coordinates in [-1, 1], a flat batch, whose points the basis shares or sparsifies.
    • Output: \((N, \text{out\_features})\).
    Evaluation on a grid

    A projection \(\mathbf{U}^{(c)\top} \boldsymbol{\varphi}(x_c)\) depends on one coordinate alone, so points on a grid, such as the pixels of an image or a batch drawn from them, share it. When every axis repeats its coordinates, the basis evaluates each distinct coordinate once and the combiner projects that table, each point gathering its rows, as FINR does with its networks. This computes the same function and gradients in \(O(R \sum_c S_c K_c + NCR)\) for \(N\) points with \(S_c\) distinct coordinates on axis \(c\), instead of \(O(NR \sum_c K_c)\), or \(O(NRL)\) for a local basis's \(L\) taps. A basis given grid_size, the grid that every input lies on, as a coordinate dataset's points do, evaluates its table there once, when it is built, and rounds each point to its row, which spares searching every batch for its distinct coordinates, a sort and a synchronization per axis. A point off the grid would read its nearest grid point, so a radiance field, whose samples are scattered, declares none. Scattered points and coordinates that need gradients are evaluated point by point.

    The tables are buffers outside the model's state_dict. Moving or casting the model, as to and double do, evaluates them again on its new device and in its new dtype, so they are exact in any precision.

    Solvers¶

    futon_solvers ¶

    Block coordinate descent for FUTON: solvers in place of a gradient optimizer.

    A FUTON with a CP combiner and a linear decoder, both without bias, is the paper's model, and it is multilinear: with the other blocks held, its output is linear in each factor matrix and in the decoder, so fitting one block is a least-squares problem. BCD sweeps the blocks once per batch and leaves each block's update to a subclass: LeastSquares solves the block's problem, for any basis, and MultiplicativeUpdate takes Lee and Seung's step, which keeps a nonnegative model nonnegative. Both are optimizers that neurofield.train takes in place of Adam, on the same datasets.

    References

    Lee and Seung, "Algorithms for non-negative matrix factorization", NeurIPS 2001. Gillis and Glineur, "Accelerated multiplicative updates and hierarchical ALS algorithms for nonnegative matrix factorization", Neural Computation 2012. Mairal, Bach, Ponce and Sapiro, "Online learning for matrix factorization and sparse coding", JMLR 2010.

    BCD ¶

    BCD(model: FUTON, momentum: float = 0.9, initialize: bool = True, **defaults: Any)

    Bases: Optimizer

    Block coordinate descent over a FUTON's factor matrices and decoder.

    On a grid with M_c coordinates along axis c the model is a CP tensor, with one factor per axis, the response T_c A_c of the basis's table T_c (M_c, K_c) and the factor matrix A_c (K_c, R), and one for the channels, the decoder W (D, R). With the other blocks held, the mean squared error's normal equations for A_c are P A_c Q = B, small and of the size of A_c: P = T_c^T T_c / M_c is the basis's Gram matrix, Q the elementwise product of W^T W and of the other axes' Gram matrices (T_j A_j)^T (T_j A_j) / M_j, and B the targets' correlation with the rest of the model. The decoder's are W G = C, with G the product of every axis's Gram matrix.

    A batch is taken as points of the grid the basis declares, or else of the grid of its distinct coordinates. The Gram matrices are the grid's, and a right-hand side is what the model explains on the grid plus what it misses at the batch's points, B = P A_c Q + T_c^T E_c / N for the residual's correlation E_c over the N points: exact on a whole grid and, on a random share of it, the whole grid's in expectation, with the noise of the residual rather than of the signal. A sweep thus costs a few products of matrices over the grid whatever share of it the batch holds, and a whole grid is where the solvers need no momentum and the fewest sweeps. There, without momentum, no update raises the batch's error.

    step updates the factors in order and then the decoder, each from the others' latest values, through a subclass's solve, and holds every axis's response at unit mean square, the decoder's columns taking the scales, which fixes the freedom of a CP model to trade scale between its blocks. compile compiles the sweep with torch.compile.

    momentum averages each block's statistics over the batches, as online matrix factorization does, with weights that sum to one from the first batch on. The newest batch's weight, 1 - momentum, is the solver's lr, which a scheduler anneals as it would a gradient step's: neurofield.train takes it down to a hundredth, so that the average reaches further back as the model settles.

    def compile(
    self, batch: Mapping[str, Tensor] | None = None, **options: Any

    """Compile the sweep with ``torch.compile``, given ``options``.

    With a ``batch``, compile it now, on that batch's shapes, and leave the

            for param, value in zip(params, saved):
                param.copy_(value)
        self.state.clear()

    MultiplicativeUpdate ¶

    MultiplicativeUpdate(model: FUTON, inner: int = 16, floor: float = 1e-12, momentum: float = 0.9, initialize: bool = True)

    Bases: BCD

    Lee and Seung's multiplicative updates, for a nonnegative model.

    With everything nonnegative, the two parts of a block's gradient are too, and the update multiplies the block elementwise by their ratio, A <- A * B / (P A Q), or sets an entry to zero where a minibatch's estimate of B is negative. That is the minimizer of the auxiliary function Lee and Seung build for a quadratic with a nonnegative Hessian: the block's problem is never worse after the update, the block stays nonnegative, and one at a fixed point stays there. A block's problem is fixed for the sweep and an update costs two small products, so each block takes inner of them in a row, as Gillis and Glineur propose.

    The model needs a nonnegative basis, the triangle with normalize=False so that its functions sum to one, nonnegative targets and nonnegative parameters, which are drawn uniformly in [0.5, 1.5] before scaling. A signal in [-1, 1] is fitted through the affine output activation lambda z: 2 * z - 1, under which the targets are its values rescaled to [0, 1].

    futon_bounds ¶

    How well a FUTON with a linear decoder can fit a sampled signal, bounded both ways.

    A FUTON with a CP combiner and a linear decoder, both without bias, is the paper's model: its weight tensor \(\mathcal{W} = [\![\mathbf{U}^{(1)}, \dots, \mathbf{U}^{(C)}, \mathbf{V}]\!]\) has CP rank at most R. On a signal's sampling grid, its error splits exactly in two: the error of the best approximation in the basis's span, which no rank removes, and the CP misfit of the signal's coefficients in an orthonormal basis of that span. futon_bound computes the first exactly and brackets the best second: from below by the singular values of the coefficients' matricizations, and from above by an explicit CP tensor, the leading terms of a nested SVD refined by alternating least squares. Its factors, mapped back through the basis, make a FUTON whose error is exactly the upper bound. Everything a bound rests on is computed in float64; only the search for the factors runs in float32, since any factors give a valid bound once their error is taken exactly. The theorem and its proof are in the documentation, under Concepts.

    # decompositions here and below run on the CPU, where they are fastest.
    bases, inverses = [], []
    for phi in features:
        phi = phi.double().cpu() / math.sqrt(len(phi))
        q, s, vh = torch.linalg.svd(phi, full_matrices=False)
        keep = s > s[0] * max(phi.shape) * torch.finfo(s.dtype).eps
        bases.append(q[:, keep])
        inverses.append(vh[keep].T / s[keep])  # B_c^+, (K_c, K_c')

    # The signal's coefficients in the orthonormal basis of the span.
    coefficients = signal
    for axis, q in enumerate(bases):
        coefficients = torch.tensordot(coefficients, q.to(signal), dims=([axis], [0]))
        coefficients = coefficients.movedim(-1, axis)
    coefficients = coefficients / math.sqrt(math.prod(sizes))
    energy = float(coefficients.square().sum())
    truncation = max(float(signal.square().mean()) * channels - energy, 0.0)

    small = coefficients.cpu()
    lower = _tails(small, ranks)

    # The upper bounds' SVD form: per rank, the R heaviest terms of the nested
    # SVD expansion along the best mode order. Modes of size one are peeled
    # first, at no cost, and the last two of an order share one SVD.
    modes = range(coefficients.ndim)
    single = [mode for mode in modes if coefficients.shape[mode] == 1]
    rest = [mode for mode in modes if coefficients.shape[mode] > 1]
    orders = [
        single + list(order)
        for order in permutations(rest)
        if len(order) < 2 or order[-2] < order[-1]
    ]
    expansions = []
    for order in orders:
        weights, vectors = _expansion(small.unsqueeze(0), order)
        weights, index = weights[0].sort(descending=True)
        vectors = [part[0, index] for part in vectors]
        kept = torch.cat([weights.new_zeros(1), weights.square().cumsum(0)])
        expansions.append((weights, vectors, kept))

    # The search runs in float32 on the signal's device; each bound is the
    # exact float64 error of the factors it finds.
    working = coefficients.float()
    upper, factors = [], []
    for rank in ranks:
        errors = [
            energy - float(kept[min(rank, len(kept) - 1)]) for _, _, kept in expansions
        ]
        weights, vectors, _ = expansions[
            min(range(len(errors)), key=errors.__getitem__)
        ]
        terms = min(rank, len(weights))
        initial = [part[:terms].T.to(working) for part in vectors]
        initial[0] = initial[0] * weights[:terms].to(working)
        chosen = _als(working, initial, sweeps, tol, truncation)
        chosen = [factor.double() for factor in chosen]
        residual = _residual(coefficients, chosen)
        # A rank's FUTON is one of every larger rank, with zero components added.
        if upper and upper[-1] < residual:
            residual, chosen = upper[-1], factors[-1]
        padded = [
            torch.cat([f, f.new_zeros(len(f), rank - f.shape[1])], 1) for f in chosen
        ]
        upper.append(residual)
        factors.append(padded)

    # Back to the basis: U^(c) = B_c^+ U~^(c), with the decoder unchanged.
    mapped = [
        (
            [inverse @ factor.cpu() for inverse, factor in zip(inverses, chosen[:-1])],
            chosen[-1].cpu(),
        )
        for chosen in factors
    ]
    to_mse = 1 / channels
    return FUTONBound(
        ranks=ranks,
        truncation=truncation * to_mse,
        lower=(truncation + lower) * to_mse,
        upper=(truncation + torch.tensor(upper, dtype=torch.float64)) * to_mse,
        factors=mapped,
    )
